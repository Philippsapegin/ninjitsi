# Ninjitsi

Desktop-first видеокомната поверх self-hosted Jitsi с собственным интерфейсом и прямой интеграцией через `lib-jitsi-meet`.

## Что уже есть

- адаптивная сетка, в которой все участники видны одновременно;
- строгое соотношение каждой видеоплитки `16:9`;
- автоматический подбор числа строк и колонок под окно и число участников;
- центрирование неполной последней строки;
- без бокового filmstrip и без мобильных компромиссов;
- вход по ссылке, имени и необязательному паролю комнаты;
- микрофон, камера, демонстрация экрана, копирование ссылки и полноэкранный режим;
- демонстрационный режим без Jitsi-сервера.

## Запуск

Нужен Node.js 20 или новее.

```bash
npm install
copy .env.example .env.local
npm run dev
```

Откройте `http://localhost:3000`.

В `.env.local` укажите корень установленного Jitsi Meet без завершающего слеша:

```dotenv
NEXT_PUBLIC_JITSI_URL=https://meet.example.com
```

Если переменная не задана, приложение запускается в демонстрационном режиме с фиктивными участниками — удобно для работы над интерфейсом.

## Требования к Jitsi

Клиент ожидает стандартные файлы установленного Jitsi Meet:

- `/config.js`;
- `/libs/lib-jitsi-meet.min.js`;
- рабочий BOSH и/или WebSocket, объявленный в `config.js`;
- корректный HTTPS-сертификат.

Клиент не требует учётных записей. Имя комнаты находится в URL. Пароль не добавляется в ссылку и хранится только в памяти вкладки. Как и обычный lock в Jitsi, пароль действует, пока существует конференция; после ухода последнего участника состояние комнаты обычно исчезает.

## Проверки

```bash
npm run typecheck
npm run lint
npm run build
npm run build:cloudflare
npm run smoke:visual
```

Визуальный smoke-тест запускает production-сборку в Chrome и проверяет сетку на `1040×720`, `1440×900` и `1920×1080`: плитки должны иметь соотношение `16:9`, не пересекать панели управления и не создавать горизонтальный скролл.

## Структура

- `app/` — страницы входа и комнаты;
- `components/meeting/` — видеосетка, плитки и управление звонком;
- `lib/jitsi/` — загрузка `lib-jitsi-meet` и жизненный цикл конференции;
- `hooks/useOptimalGrid.ts` — расчёт оптимальной геометрии плиток.

Production-сборка упаковывается как статический SPA Worker: серверная логика для звонка не нужна, а маршруты вида `/room/<name>` отдаются через единый клиентский shell. Это оставляет Jitsi-сигналинг непосредственно между браузером и целевым Jitsi-сервером.

## Текущее ограничение

Интеграционный слой подготовлен для self-hosted Jitsi, но для окончательной проверки сигналинга, паролей, TURN и screen sharing нужен адрес целевого сервера. До этого опубликованная сборка работает как интерактивное UI-демо.
