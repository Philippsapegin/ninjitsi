# API внешних ботов, версия 1

Бот — внешняя программа, которая читает команды общего чата и публикует ответы
в том же чате с отметкой «бот». Отдельная видеоплашка и микрофон ему не нужны.
Движок кубов, выполнение команд и сами боты в Ninjitsi не включены.
Например, будущий бот может обработать `/roll 2d20+3` и вернуть текст
`2d20+3: [12, 4] + 3 = 19`. Выражение и модификаторы разбирает бот.

## Подключение

Сначала создайте комнату обычным способом и скопируйте её код из ссылки.
На сервере задайте переменную `NINJITSI_BOTS` — JSON-массив:

```dotenv
NINJITSI_BOTS='[{"id":"dice","name":"Кубы","token":"<случайный ключ не короче 32 символов>","rooms":["<полный-код-комнаты>"]}]'
```

Сгенерировать ключ можно командой `openssl rand -hex 32`. Сохраните его только
в конфигурации сервера и внешнего бота. Клиентам комнаты этот ключ не передаётся.
Идентификаторы и ключи ботов должны быть уникальны; до 50 ботов, до 100 явных
кодов комнат у каждого. Маска `*` запрещена. Это даёт боту доступ именно
к перечисленным комнатам, включая защищённые паролем; такой доступ назначает
администратор сервера. Удаление ключа или комнаты из конфигурации отзывает доступ
после перезапуска контейнера Ninjitsi.

Compose передаёт переменную в контейнер. После изменения `.env` пересоздайте
контейнер Ninjitsi в подходящий момент; Jitsi для этого менять не требуется.
Участники должны заново войти в комнату, чтобы получить разрешение на связь с API.
Без конфигурации ботов API выключен, клиент не отправляет туда чат.
Статический хостинг без `server/server.mjs` этот API не предоставляет.

Все запросы идут к домену Ninjitsi по HTTPS с заголовком:

```http
Authorization: Bearer <ключ бота>
```

Ключи нельзя передавать в query string. API не принимает браузерные cookies
вместо ключа и не включает CORS для сторонних сайтов.

## Чтение команд

```http
GET /api/v1/rooms/{code}/events?after=0
```

Пример ответа:

```json
{
  "version": 1,
  "epoch": "случайный-идентификатор-запуска-сервера",
  "cursor": 7,
  "truncated": true,
  "events": [{
    "sequence": 7,
    "id": "botchat-идентификатор-запуска-7",
    "type": "message.created",
    "requestId": "исходный-id-сообщения",
    "actorId": "идентификатор-сессии-отправителя",
    "senderId": "user:идентификатор-сессии-отправителя",
    "senderName": "Алиса",
    "isBot": false,
    "text": "/roll 2d20+3",
    "timestamp": 1794096000000
  }]
}
```

Для следующего запроса сохраните `epoch` и `cursor` из ответа и передайте их
как `?after=7&epoch=...`. Опрос раз в 2 секунды достаточен. Обрабатывайте только
новые `id`, `type: message.created`, `isBot: false` и нужный префикс команды.
В потоке есть ответы всех ботов; их следует пропускать, чтобы не создавать петли.
`senderId` относится к сессии API и не является Jitsi endpoint ID.

`truncated: true` означает смену запуска сервера или пропущенные события,
которые уже вышли за пределы хранения. Первый запрос без `epoch` также имеет
`truncated: true`. После смены `epoch` сервер начинает чтение с доступных событий,
даже если старый `after` больше нового счётчика. Счётчик общий для процесса,
поэтому пропуски номеров между событиями одной комнаты нормальны.

## Ответ в чат

```http
POST /api/v1/rooms/{code}/messages
Content-Type: application/json

{"id":"roll-command-7","text":"2d20+3: [12, 4] + 3 = 19"}
```

Ответ `201` содержит `{ "event": { ... } }`. Клиенты получают его при очередном
опросе и отображают один раз под серверным именем бота. Бот не может назначить
себе имя участника через тело запроса. Текст — обычный текст, без HTML и выполнения
кода. Нотация кубов не ограничена API.

`id` — обязательный ключ повтора: 1–100 латинских букв, цифр, `_` и `-`.
`text` — непустая строка до 4000 символов. Другие поля отклоняются. Повтор POST
с тем же `id` от того же бота возвращает ранее созданное событие, пока оно
сохраняется. Если текст изменился, используйте новый `id`. Для надёжного бота
храните обработанные команды и ответы у себя: серверный журнал временный.

## Передача сообщений участника

После обычного `POST /api/rooms/{code}/join` допущенный пользователь получает
дополнительное поле `eventsToken`. Оно `null`, если боты не настроены для комнаты.
Ninjitsi хранит токен в активной странице и автоматически передаёт **только свои
исходящие общие текстовые сообщения** в:

```http
POST /api/v1/rooms/{code}/events
Authorization: Bearer <eventsToken>
Content-Type: application/json

{"id":"id-сообщения-чата","text":"/roll 2d20+3"}
```

Личный текст, вложения, аудио, видео и полученные Jitsi сообщения не передаются.
Клиентам старых версий недоступна передача команд через этот мост — им нужно
обновить страницу. Основной Jitsi чат продолжает работать при отказе API;
Ninjitsi показывает отдельное уведомление о недоступности ботов. Доставка
временного моста не гарантирует выполнение каждой команды после длительного
отключения. Ошибки при отправке повторяются ограниченное число раз с тем же `id`.

С `eventsToken` можно читать `/events`, но ответ содержит только сообщения ботов.
Публиковать `/messages` участник не может; бот не может публиковать `/events`
от имени человека. Токен участника действует до 12 часов и ограничен комнатой
и сроком её существования. При истечении токена нужно заново войти. В открытом
режиме Jitsi перезапуск Ninjitsi также отзывает эти токены; в JWT-режиме подпись
стабильна до изменения общего секрета.

## Ограничения

- События находятся в памяти одного процесса: до 30 минут, 500 событий на
  комнату и 10 000 на весь процесс. Они исчезают после перезапуска. При наличии
  ботов общий текст проходит через сервер Ninjitsi и становится доступен
  всем настроенным для этой комнаты ботам; учтите это при приглашении игроков.
- API не объединяет несколько реплик сервера. Для масштабирования нужен общий
  журнал; текущая установка рассчитана на один процесс Ninjitsi.
- До 120 запросов в минуту на сессию/бота, до 30 публикаций в минуту на
  сессию/бота и до 600 публикаций в минуту на процесс. При `429` учитывайте
  `Retry-After`. Неуспешные попытки тоже расходуют лимит.
- `400`: некорректный запрос; `401`: неверный, истёкший ключ или другая комната;
  `403`: запрещённый метод/роль или отключённый API; `404`: комната истекла;
  `413`: слишком большое тело; `429`: ограничение частоты.
- API не даёт боту медиадоступ, модерацию комнаты, личную переписку или историю
  до обновления клиентов. Обработку команд, генератор случайных чисел и хранение
  игровых данных реализует внешний бот.
